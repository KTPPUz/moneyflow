# เป้าหมายเงินออมและการแจ้งเตือน

ขอบเขตที่ผู้ใช้ขอเพิ่มเติมจาก PRD: เป้าหมายเงินออมพร้อมยอดสะสมและจำนวนที่ควรออมต่อเดือน และแจ้งเตือนงบใกล้หมดกับวันครบกำหนดจ่าย ไม่มีข้อมูลตัวอย่างเริ่มต้น

## การใช้งานและการคำนวณ

- `/goals`: สร้าง แก้ไข ลบเป้าหมาย กำหนดยอดและวันที่เป้าหมาย เพิ่มยอดออมตั้งต้นหรือรายการออมภายหลัง ดูประวัติและลบรายการที่ผิดได้ ยอดสะสมรวมจากประวัติของเป้าหมายนั้น
- จำนวนที่ควรออมต่อเดือน = ยอดที่ยังขาด / จำนวนเดือนปฏิทินที่เหลือ **รวมเดือนปัจจุบันและเดือนเป้าหมาย** ปัดขึ้นเป็นสตางค์ด้วย BigInt เช่น ขาด 6,667 สตางค์ อีก 3 เดือน ต้องออมเดือนละ 2,223 สตางค์ เมื่อเลยกำหนดแสดงยอดที่ยังขาดเป็นยอดที่ควรเติมทันที เมื่อสำเร็จแสดงยอดที่ควรออมเป็นศูนย์
- ประวัติออมต้องไม่ลงวันที่ในอนาคต ยอดสะสมเกินเป้าหมายได้ การติดตามออมไม่ใช่การย้ายเงินระหว่างบัญชีและไม่สร้างรายจ่าย จึงไม่กระทบยอดบัญชีหรือกระแสเงินสดเดิม
- `/reminders`: เพิ่ม แก้ไข ลบบิลครั้งเดียว กำหนดวันจ่ายและเริ่มเตือน 0/1/3/7/14/30 วันล่วงหน้า บิลเลยกำหนดยังเตือนจนทำเครื่องหมายชำระแล้ว สามารถเปิดกลับเป็นยังไม่ชำระได้ การทำเครื่องหมายเป็นสถานะเตือนเท่านั้น ต้องบันทึกรายจ่ายจริงในหน้ารายการ
- เตือนงบ **เดือนปัจจุบันใน Asia/Bangkok** แยกจากเดือนที่เลือกดูย้อนหลัง เตือนตั้งแต่ 80%, เมื่อถึง 100% และเกิน 100% งบรวมมาจากรายรับที่บันทึก รายหมวดใช้รายจ่ายสุทธิรวมหมวดย่อยและหักคืนเงิน เมื่อไม่มีรายรับแต่มีรายจ่ายมีข้อความอธิบายแทนสัดส่วนที่หารศูนย์ไม่ได้
- กระดิ่งแสดงจำนวนยังไม่อ่านจากรายการเตือนจริง ทำเครื่องหมายทีละรายการหรือทั้งหมดได้ สถานะจำในฐานข้อมูล เมื่อความรุนแรงเปลี่ยนจากใกล้เต็มเป็นถึงงบ/เกินงบ หรือบิลเปลี่ยนจากใกล้จ่ายเป็นวันนี้/เลยกำหนด จะเป็นการเตือนใหม่
- การแจ้งเตือนเป็น **ภายในแอปเมื่อเปิดใช้งาน** ไม่ส่งข้อความ LINE, อีเมล, browser push หรือทำงานขณะปิดเว็บ ตรวจวันใหม่ทุกนาทีและเมื่อกลับเข้าแท็บ

## ข้อมูลและการติดตั้ง

Prisma migration `20261031170000_savings_and_reminders` เพิ่มเฉพาะตาราง `planning_states`, `savings_goals`, `goal_contributions`, `bill_reminders` ใช้เงิน DECIMAL(15,2), client ใช้ integer satang มี composite foreign key แยกตามผู้ใช้ ไม่มีการย้าย/ลบรายการการเงินเดิม

ใช้ `npx prisma migrate deploy` กับฐานข้อมูลที่ต้องการหลังตรวจ `DATABASE_URL` แล้ว Vercel build command เดิม `npm run vercel-build` ทำ migrate ก่อน build อยู่แล้ว ในการพัฒนารอบนี้ทดสอบ migration กับฐานข้อมูลชั่วคราว ไม่ใช้ข้อมูลการเงินจริง

`GET/PUT /api/planning` ตรวจ session, บังคับ user ID จาก session, validate ทุกช่องและการอ้างอิงเป้าหมายที่ server, ไม่ cache ข้อมูลส่วนบุคคล และตรวจ Origin ของ PUT ผ่าน Host ที่ผู้ใช้เรียก (Next/proxy อาจมี URL ภายในต่างกัน) ไม่รับ user ID จาก body

บันทึกใช้ transaction และ revision เพื่อปฏิเสธข้อมูลเก่าด้วย 409 ฝั่ง client โหลดล่าสุดแล้วใช้การแก้ไขเดิมซ้ำหนึ่งครั้ง โดยทำงานเป็นคิว ไม่เขียนทับการเปลี่ยนจากอุปกรณ์อื่นแบบเงียบ ๆ หากบันทึกไม่ผ่านคงค่าฟอร์มและแสดงสาเหตุ ไม่แจ้งสำเร็จล่วงหน้า

การล้างข้อมูลบัญชีเดิมครอบคลุมเป้าหมาย ประวัติออม บิล และสถานะอ่านแล้ว ใน transaction เดียวกับข้อมูลการเงิน และไม่มีผลต่อผู้ใช้อื่น

## การทดสอบ

- `tests/planning.test.ts`: สูตรเงินออม เศษสตางค์ เดือน/ปี/วันที่อธิกสุรทิน บิลเลยกำหนด/ชำระแล้ว การเตือนงบและคืนเงิน การเปลี่ยนระดับแจ้งเตือน validation และ Origin หลัง proxy
- `tests/browser/planning.spec.ts`: ทดสอบบนฐานข้อมูลแยกเท่านั้น เปิดด้วย `E2E_PLANNING=true` และ `E2E_BASE_URL` ที่ชี้ test server ตรวจ CRUD, reload persistence, ข้อผิดพลาด, บัญชีผู้ใช้แยกกัน, revision conflict, reset และ desktop/mobile layout
- ห้ามรัน E2E กับฐานข้อมูลส่วนตัวหรือ production เพราะชุดทดสอบจะสร้างผู้ใช้และรายการทดสอบ

ผลตรวจรอบนี้: unit tests 26 กลุ่มผ่าน; browser tests 26 กรณีผ่าน (ข้าม 6 กรณีซ้ำของ flow เดิมบน tablet/1024 ตาม config เดิม) ครอบคลุม 390/768/1024/1440px, Light/Dark, ใช้ MySQL 5.7 ชั่วคราวบนเครื่องสำหรับทดสอบ migration และ CRUD ไม่ได้ใช้ฐานข้อมูล TiDB จริง Production build, TypeScript และ lint ผ่านโดยมีคำเตือน navigation เดิม 3 จุด

บันทึกการตรวจคำขอบันทึก: รอบแรกฟอร์มได้รับ 403 ก่อนตรวจ session การส่งคำขอ local โดยมี Origin `http://127.0.0.1:3004` ได้ 403 แต่ไม่มี Origin หรือเปลี่ยน Origin เป็น `http://localhost:3004` ได้ 401 ยืนยันว่า Next ใช้ URL ภายในต่างจาก Host ของผู้ใช้ เปลี่ยนการตรวจเป็น public Host และยังปฏิเสธ Origin ต่างเว็บไซต์/opaque origin ด้วย unit test และ browser flow เดิมผ่าน ตรวจภาพพบ summary ใช้ selector `.card` แต่ component จริงเป็น `.panel` จึงแก้ selector และเพิ่ม assertion ว่าตัวเลขอยู่ใต้ label
